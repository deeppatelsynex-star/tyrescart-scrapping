Building a scraper for this app

This page documents the exact structure another developer needs to follow to write a new scraper script (site_a.py, site_b.py, my_scraper.py, ...) that this web app can run. It's based on one of the app's existing, working scrapers as a reference implementation. Every code sample below is taken directly from a real, working script.

Architecture

Web Application
      ↓  (starts the process, passes 2 arguments)
Uploaded Python Scraper
      ↓
Scrapy Spider  (your class)
      ↓
Entry URLs from a CSV file  →  Scraping  →  URL_STATUS lines on stdout
      ↓
XLSX Output written to the path the web app gave you
      ↓
Web Application  (reads status lines live, serves the finished file for download)

The web app's job

Launch your script as a subprocess, pass it an output path and an input CSV path, watch its stdout for progress, and serve the file it produced.

Your script's job

Read the input, make requests, extract data, optionally report progress, write the output to the exact path given, and exit cleanly.

Script structure

Every compatible script is one Scrapy Spider subclass, started by a CrawlerProcess at the bottom of the file. Lay it out in this order:

from scrapy import Spider, Request, Selector
from scrapy.crawler import CrawlerProcess


class MyScraper(Spider):
    name = "my_scraper"          # unique spider name

    # OUTPUT FILE      -- resolves sys.argv[1]
    # CSV / INPUT FILE -- resolves sys.argv[2]
    # SETTINGS         -- custom_settings, incl. FEEDS for xlsx export
    # HEADERS          -- default request headers

    def __init__(self, *args, **kwargs):
        ...                       # tracking state (sets/dicts), see "Request tracking"

    def emit_status(self, url, status, parent=None, url_type=None):
        ...                       # prints URL_STATUS lines, see "URL status protocol"

    # REQUEST FUNCTIONS  -- make_tracked_request(), request_failed(), etc.

    async def start(self):
        ...                       # reads the input CSV, seeds the first requests

    def parse_input_url(self, response):
        ...                       # routes an entry URL to a listing or detail parser

    def parse_listing(self, response):
        ...                       # website-specific: find product links + pagination

    def parse_detail(self, response):
        ...                       # website-specific: extract one item, yield it

    # HELPER FUNCTIONS   -- optional: text/price/URL cleanup


if __name__ == "__main__":
    process = CrawlerProcess(MyScraper.custom_settings)
    process.crawl(MyScraper)
    process.start()
The Spider class itself is required. The app runs your file with python your_script.py <output> <input_csv> — it never imports your class or calls a function directly. Everything has to happen from your file's own if __name__ == "__main__": block, exactly like the reference script.

Runtime arguments — the most important part

The web app starts your script like this: 

python your_scraper.py  OUTPUT_FILE  INPUT_CSV

# e.g.
python your_scraper.py  /tmp/scrapers/job_ab12cd34_listing_output.xlsx  /tmp/scrapers/job_ab12cd34_listing.csv
ArgumentMeaning
sys.argv[1]The exact path your finished .xlsx must be written to.
sys.argv[2]A CSV of seed URLs, one per line, no header — the first column is the URL.

From the reference script — read both with a fallback default so the file also still runs standalone during local testing:

# OUTPUT FILE
base_dir = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
today = datetime.now().strftime("%d-%m-%Y")

output_file = sys.argv[1] if len(sys.argv) > 1 else os.path.join(
    base_dir, f"scraper_data_{today}.xlsx"
)

# CSV FILE
csv_file = sys.argv[2] if len(sys.argv) > 2 else os.path.join(
    base_dir, "testurls.csv"
)
Do not invent your own output filename or hardcode an input path. The app never searches for output files — it only ever looks at the exact path it gave you in sys.argv[1]. If your script writes somewhere else, the app will report "no output available" even though your script ran successfully.

Reading the CSV — one URL per line, first column only:

with open(self.csv_file, newline='', encoding='utf-8') as f:
    reader = csv.reader(f)
    for row in reader:
        if not row:
            continue
        source_url = row[0].strip()
        if not source_url.startswith("http"):
            continue

Scrapy settings & XLSX output

The app doesn't build your output file for you — scrapy-xlsx's feed exporter does, driven entirely by custom_settings. This is the block that matters: 

custom_settings = {
    "FEED_EXPORTERS": {
        "xlsx": "scrapy_xlsx.XlsxItemExporter"
    },
    "COOKIES_ENABLED": True,
    "FEEDS": {
        output_file: {              # <-- must be the sys.argv[1] path, not a literal string
            "format": "xlsx",
            "encoding": "utf8",
            "store_empty": False,
        }
    },
    "DOWNLOAD_DELAY": 0.5,
    "CONCURRENT_REQUESTS": 3,
    "LOG_LEVEL": "INFO",
}
  • FEED_EXPORTERS registers the xlsx format with Scrapy (needs the scrapy-xlsx package installed).
  • FEEDS is the actual export target — the dict key is the file path, so it must be the output_file variable, evaluated after you've already resolved sys.argv[1] above it.
  • Every dict/list your parse methods yield becomes one row — the column headers come from the first item's keys, in order, so use an OrderedDict if column order matters (see "Detail extraction").
  • DOWNLOAD_DELAY / CONCURRENT_REQUESTS are yours to tune per target site; they don't affect app compatibility.

If you'd rather export CSV or JSON instead of xlsx, swap the FEEDS format accordingly (Scrapy supports "csv" and "json" natively, no extra package needed) — just make sure the path you write to is still exactly output_file, whatever its extension.

URL status protocol

This is how the app shows a live progress tree while your script runs. It works by reading your script's stdout, line by line, looking for a specific format — it does not parse Scrapy logs or guess progress any other way. 

URL_STATUS|URL|STATUS|PARENT|URL_TYPE

URL_STATUS|https://example.com|pending||root
URL_STATUS|https://example.com/product/1|running|https://example.com|product
URL_STATUS|https://example.com/product/1|done|https://example.com|product
URL_STATUS|https://example.com/product/1|blocked|https://example.com|product
def emit_status(self, url, status, parent=None, url_type=None):
    print(f"URL_STATUS|{url}|{status}|{parent or ''}|{url_type or ''}")

Supported statuses

StatusMeaning
pendingURL has been discovered/queued, not yet requested.
runningThe request for this URL is currently in flight.
doneFinished successfully (item extracted, or page fully processed).
blockedRequest failed, or the site returned a 403 / blocked response.
Don't invent a fifth status — the app's parser (parse_status_line / build_status_summary) only recognizes these four words.

Parent & type

parent tells the app which URL discovered this one, so it can render a tree instead of a flat list; url_type is just a small label for the UI badge. The reference script uses root (a seed URL from the CSV), listing (a paginated category page), and product (a detail page):

Root URL (url_type="root", no parent)
   │
   ├── Listing page 2   (url_type="listing", parent=root)
   ├── Product URL 1    (url_type="product", parent=root)
   ├── Product URL 2    (url_type="product", parent=root)
   └── Product URL 3    (url_type="product", parent=root)
self.emit_status(product_url, 'pending', parent=source_url, url_type='product')

Request tracking

A root URL isn't "done" the moment its own page loads — it's done once every child request it spawned (products, extra listing pages) has also finished. The reference script tracks this with a simple counter per source URL: 

def __init__(self, *args, **kwargs):
    super().__init__(*args, **kwargs)
    self.pending_requests = {}      # source_url -> count of in-flight child requests
    self.failed_sources = set()

def make_tracked_request(self, url, source_url, callback):
    self.pending_requests[source_url] = self.pending_requests.get(source_url, 0) + 1
    return Request(
        url=url,
        callback=callback,
        errback=self.request_failed,
        headers=self.headers,
        meta={'source_url': source_url, 'display_url': url},
        dont_filter=True,
    )

def finish_source_request(self, source_url):
    remaining = self.pending_requests.get(source_url, 1) - 1
    if remaining > 0:
        self.pending_requests[source_url] = remaining
        return
    self.pending_requests.pop(source_url, None)
    status = 'blocked' if source_url in self.failed_sources else 'done'
    self.emit_status(source_url, status)
Source URL
    │
    ├── Product Request 1  ─┐
    ├── Product Request 2   ├─  each finishes → finish_source_request(source_url)
    ├── Product Request 3   │
    └── Next Page Request  ─┘
                              ↓
              counter reaches 0 → Source URL emitted as done (or blocked)

Request creation fields

callbackWhere the response goes on success (parse_listing, parse_detail, ...).
errbackrequest_failed — reports blocked and still closes out the tracking counter, so a failed request never leaves its source URL stuck at "running" forever.
meta.source_urlWhich root URL this request ultimately belongs to — read back via self.source_url(response).
meta.display_urlThe URL to actually show/emit status for (usually the request's own URL).
dont_filterTrue — Scrapy's default duplicate-URL filter would otherwise silently drop a legitimately-revisited URL (e.g. pagination).

Error handling

def request_failed(self, failure):
    source_url = self.source_url(failure)
    self.emit_status(self.display_url(failure), 'blocked')
    self.failed_sources.add(source_url)
    self.logger.error('Request failed for %s: %s', failure.request.url, failure.value)
    self.finish_source_request(source_url)

Any failed request should: emit blocked for itself, record its source as failed, and still call finish_source_request — skipping that last step is the single most common way a scraper "hangs" from the app's point of view (the root URL's counter never reaches zero, so it's shown as running forever).

Entry URL routing

A URL from the input CSV isn't necessarily a listing page — a user might paste a direct product URL instead. The reference script sniffs the response and routes accordingly: 

def parse_input_url(self, response):
    is_product_page = bool(response.css(
        'h1[itemprop="name"], .product-info-price, #product-addtocart-button'
    ).get())

    if is_product_page:
        yield from self.parse_detail(response)
    else:
        yield from self.parse_listing(response)
Entry URL
   │
   ├── looks like a product page  → parse_detail()
   │
   └── otherwise (a listing page) → parse_listing()

Swap the CSS selectors for whatever uniquely identifies a product page on your target site — the routing pattern itself (one entry parser dispatching to two others) is what's worth keeping.

Listing page & pagination

Website-specific — replace every selector below with ones from your target site. The pattern (find links, track them, follow the next page) is what to keep.

product_links = response.css('a.product-item-link::attr(href)').getall()

for link in product_links:
    product_url = response.urljoin(link)
    product_key = self.normalise_url(product_url)
    if not product_key or product_key in self.seen_detail_urls:
        continue
    self.seen_detail_urls.add(product_key)
    self.emit_status(product_url, 'pending', parent=source_url, url_type='product')
    yield self.make_tracked_request(product_url, source_url, self.parse_detail)

next_page = response.css(
    'a.next::attr(href), .pages-item-next a::attr(href), a.action.next::attr(href)'
).get()
if next_page:
    next_page_url = response.urljoin(next_page)
    self.emit_status(next_page_url, 'pending', parent=source_url, url_type='listing')
    yield self.make_tracked_request(next_page_url, source_url, self.parse_listing)
Listing Page 1 → next → Listing Page 2 → next → Listing Page 3 → no next → finished

Product detail extraction

Build an OrderedDict so your output columns come out in a predictable order, then yield it — that's what actually becomes a row in the xlsx feed. 

item = OrderedDict()
item['Product Name'] = response.css('h1::text').get('').strip()
item['Price'] = response.css('.price::text').get('').strip()
item['Category'] = response.css('.breadcrumb .active::text').get('').strip()
item['Image'] = response.css('[property="og:image"]::attr(content)').get('')
item['Source'] = response.url

yield item

Field names and count are entirely up to you — the reference script's own field list (SKU, brand, size, pricing, label ratings, ...) is specific to that script's target site and not required by the app in any way.

Helper functions & the main entry point

Optional helpers (URL normalization, text cleanup, price parsing) keep parse methods readable — the reference script's normalise_url() and get_sel_text() are examples, not requirements. What is required is starting the crawl at the bottom of the file: 

if __name__ == "__main__":
    process = CrawlerProcess(MyScraper.custom_settings)
    process.crawl(MyScraper)
    process.start()
Note on seeding requests: the reference script uses Scrapy's newer async def start(self): generator. If your installed Scrapy version doesn't support it, the classic def start_requests(self): generator works exactly the same way as far as the app is concerned — it only ever watches your stdout and your output file, never how you seed requests internally.

Complete template

Copy this, rename the class/spider name, and replace the marked sections with your target site's logic.

import os
import sys
import csv
from datetime import datetime
from collections import OrderedDict

from scrapy import Spider, Request
from scrapy.crawler import CrawlerProcess


class MyScraper(Spider):
    name = "my_scraper"                                    # CUSTOMIZE

    # ---- OUTPUT FILE (KEEP) ----
    base_dir = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
    today = datetime.now().strftime("%d-%m-%Y")
    output_file = sys.argv[1] if len(sys.argv) > 1 else os.path.join(
        base_dir, f"my_scraper_data_{today}.xlsx"
    )

    # ---- INPUT CSV (KEEP) ----
    csv_file = sys.argv[2] if len(sys.argv) > 2 else os.path.join(
        base_dir, "testurls.csv"
    )

    # ---- SETTINGS (KEEP structure, tune values) ----
    custom_settings = {
        "FEED_EXPORTERS": {"xlsx": "scrapy_xlsx.XlsxItemExporter"},
        "COOKIES_ENABLED": True,
        "FEEDS": {output_file: {"format": "xlsx", "encoding": "utf8", "store_empty": False}},
        "DOWNLOAD_DELAY": 0.5,
        "CONCURRENT_REQUESTS": 3,
        "LOG_LEVEL": "INFO",
    }

    headers = {"User-Agent": "Mozilla/5.0", "Accept-Language": "en-US,en;q=0.9"}

    def __init__(self, *args, **kwargs):                    # KEEP
        super().__init__(*args, **kwargs)
        self.pending_requests = {}
        self.failed_sources = set()
        self.seen_detail_urls = set()

    def emit_status(self, url, status, parent=None, url_type=None):   # KEEP exactly
        print(f"URL_STATUS|{url}|{status}|{parent or ''}|{url_type or ''}")

    def make_tracked_request(self, url, source_url, callback):        # KEEP
        self.pending_requests[source_url] = self.pending_requests.get(source_url, 0) + 1
        return Request(
            url=url, callback=callback, errback=self.request_failed,
            headers=self.headers, meta={'source_url': source_url, 'display_url': url},
            dont_filter=True,
        )

    def finish_source_request(self, source_url):                      # KEEP
        remaining = self.pending_requests.get(source_url, 1) - 1
        if remaining > 0:
            self.pending_requests[source_url] = remaining
            return
        self.pending_requests.pop(source_url, None)
        status = 'blocked' if source_url in self.failed_sources else 'done'
        self.emit_status(source_url, status)

    def request_failed(self, failure):                                # KEEP
        source_url = failure.request.meta.get('source_url', failure.request.url)
        self.emit_status(failure.request.meta.get('display_url', failure.request.url), 'blocked')
        self.failed_sources.add(source_url)
        self.finish_source_request(source_url)

    async def start(self):                                             # CUSTOMIZE (reads input)
        with open(self.csv_file, newline='', encoding='utf-8') as f:
            for row in csv.reader(f):
                if not row:
                    continue
                source_url = row[0].strip()
                if not source_url.startswith("http"):
                    continue
                self.emit_status(source_url, 'pending', url_type='root')
                yield self.make_tracked_request(source_url, source_url, self.parse_input_url)

    def parse_input_url(self, response):                               # CUSTOMIZE (detect page type)
        yield from self.parse_listing(response)

    def parse_listing(self, response):                                 # CUSTOMIZE (website-specific)
        source_url = response.meta.get('source_url', response.url)
        self.emit_status(response.url, 'running')
        try:
            for link in response.css('a.product-item-link::attr(href)').getall():
                product_url = response.urljoin(link)
                key = product_url.rstrip('/')
                if key in self.seen_detail_urls:
                    continue
                self.seen_detail_urls.add(key)
                self.emit_status(product_url, 'pending', parent=source_url, url_type='product')
                yield self.make_tracked_request(product_url, source_url, self.parse_detail)
        finally:
            self.emit_status(response.url, 'done')
            self.finish_source_request(source_url)

    def parse_detail(self, response):                                  # CUSTOMIZE (website-specific)
        source_url = response.meta.get('source_url', response.url)
        self.emit_status(response.url, 'running')
        try:
            item = OrderedDict()
            item['Name'] = response.css('h1::text').get('').strip()
            item['Price'] = response.css('.price::text').get('').strip()
            item['Source'] = response.url
            yield item
        finally:
            self.emit_status(response.url, 'done')
            self.finish_source_request(source_url)


if __name__ == "__main__":                                             # KEEP
    process = CrawlerProcess(MyScraper.custom_settings)
    process.crawl(MyScraper)
    process.start()

The compatibility rule

A scraper does not become compatible with this app simply because it's written in Python or Scrapy. It has to follow the app's conventions specifically.

Application-required

  • sys.argv[1] / sys.argv[2]
  • output_file written to the given path
  • custom_settings / FEEDS
  • URL_STATUS lines (if you want a live tree)
  • CrawlerProcess startup

Website-specific (yours)

  • CSS/XPath selectors
  • Output item fields
  • Listing/pagination logic
  • Stock/price/brand extraction

The scraper script this guide is based on is the reference implementation for all of the "application-required" conventions above — not every line in it is mandatory (its selectors, item fields, and stock-detection logic are entirely specific to that script's own target site and don't need to be copied).

Troubleshooting

Output file not found

Cause: your script finished but never wrote to sys.argv[1]. Fix: make sure FEEDS uses the output_file variable, or that you explicitly save to that exact path.

Wrong output path

Cause: the script created a file somewhere else (e.g. a hardcoded name). Fix: always resolve the path from sys.argv[1], never a literal string.

Progress tree stays empty

Cause: your script never prints URL_STATUS lines. This is optional — Start/Stop and the Running/Finished status still work without it, you just won't get a per-URL tree.

A URL is stuck at "running" forever

Cause: a request for that source URL failed without going through errback/finish_source_request, so its pending-request counter never reaches zero. Fix: make sure every request that can fail has an errback that still calls finish_source_request.

Script exits immediately, no output, no error

Cause: usually an exception raised before CrawlerProcess.start() is reached (e.g. reading sys.argv[2] when it wasn't given). Test locally first with both arguments supplied.
